# Design Philosophy

ScholarEcho exists because passive notes do not reliably become active knowledge.

The user should not need to reread old summaries by willpower. The system should make old knowledge resurface when it becomes relevant to the current question.

## What This Project Is

A small local research context engine that makes old knowledge echo back into current research tasks.

It helps answer:

- What do I already know about this question?
- Which papers support or challenge this idea?
- Which concepts or methods should be brought into the current task?
- What changed in my understanding after reading something new?
- What can be reused in a proposal, paper, or experiment plan?

## What This Project Is Not

- Not a full academic CMS.
- Not a perfect knowledge graph.
- Not a replacement for Zotero.
- Not a place to generate endless summaries.
- Not a system that grows new folders for every possible future need.

## The Core Rule

Every durable note should improve at least one of these:

- retrieval
- connection
- questioning
- writing
- decision-making

If it does not, keep it in the inbox or leave it out.

## The Default Unit of Progress

The default unit is not "one more summary."

The default unit is:

```text
one old or new idea connected to one active research question
```

## Good Notes Are Searchable and Reusable

A good note has:

- names and aliases people might search for
- trigger terms that should activate it
- links to related questions
- evidence and limits
- a clear "use when" section

## Keep the System Small

Add structure only when it removes repeated friction. Prefer improving templates, retrieval, and weekly synthesis before adding new subsystems.

# Operating Principles

## Start From The Current Question

Do not begin by asking "what should I summarize?" Begin by asking "what question am I trying to answer?"

The fastest entry point is:

```bash
make session q="current question"
```

## Retrieve Before Writing

Search existing notes before creating new ones. Use exact keywords, aliases, trigger terms, project seeds, and related questions.

## Keep Zotero and the Vault Separate

Zotero remains the source of truth for bibliographic metadata and PDFs. The vault is the source of truth for structured research understanding.

## Require Traceability

Claims should point back to a paper, a user note, or a clear inference. If the evidence is weak, mark it.

## Make Questions the Center of Gravity

Every paper should eventually connect to a question, project, method, or concept. A paper with no connection is only stored, not integrated.

## Write Activation Cues

Use `trigger_terms`, `aliases`, `related_questions`, and `use_when` so notes can resurface later.

## Automate Slowly

Start with Markdown, local search, and manual review. Add MCP, vector search, and automatic writes only after the retrieval behavior is useful.

## Prefer Useful Small Notes

Long summaries are easy to produce and hard to reuse. Prefer smaller notes that make retrieval, connection, questioning, writing, or decisions easier.
